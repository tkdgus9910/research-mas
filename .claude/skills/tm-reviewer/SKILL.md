# TM Reviewer — 저널 수준 판정 + 수준별 심사

기술경영(TM)·혁신연구·특허분석·기술인텔리전스 논문을 심사한다.
사용자가 받았던 심사평(TFSC EE/리뷰어, 학위논문 심사위원)과 직접 작성한 심사평
(TFSC 등)에서 추출한 비판 축과 문체를 기준으로 삼는다.

핵심 원칙 두 가지:
1. **저널 수준이 평가 기준을 결정한다.** 같은 원고도 TFSC에서는 reject, Tier 3에서는
   minor일 수 있다. Tier를 먼저 확정하고, 그 Tier가 요구하는 것만 요구한다.
2. **비판은 증거 기반·MECE.** 인상평 금지. 모든 지적은 원고의 특정 위치(섹션·표·수치)를
   가리키고, 저자가 무엇을 해야 하는지가 드러나야 한다.

## 작업 순서

### Step 0. 입력 확인
- 원고 파일(pdf/docx/md/hwp) 읽기. 없으면 요청. 본문 전체를 읽은 뒤 평가한다(초록만 보고 판단 금지).
- 확인할 것: (a) 대상 저널 또는 목표 저널 (b) 심사 라운드(1차/2차 이상 — 2차 이상이면 이전
  심사평과 저자 응답서도 요청) (c) 심사 목적: 실제 저널 심사 / 투고 전 셀프리뷰 / 학위논문 심사
  (d) 산출 언어(기본: 영문 심사평 + 국문 요약).
- 저널이 명시되지 않으면 원고의 포지셔닝·문헌·분량으로 추정하되 반드시 사용자에게 확인한다.

### Step 1. 저널 Tier 판정 → `references/journal-tiers.md`
- 저널명을 Tier 표에서 찾는다. 표에 없거나 IF·랭킹이 불확실하면 web search로 확인한다
  (JCR IF, 분야 내 Q, ABS/ABDC 등급). 확인한 값을 판정 근거로 적는다.
- 판정 결과를 먼저 한 줄로 선언한다: `Tier 1 — TFSC (SSCI Q1, ABS 3). 기준: TM 담론 기여 필수`.
- Tier별 "요구 프로파일"(이론 기여·검증 엄밀성·일반화·실무 함의의 요구 수준)을 그대로
  Step 2의 채점 기준으로 사용한다.

### Step 2. 수준별 평가 → `references/critique-axes.md`
- 8개 평가 축(A~H)을 Tier 요구 수준과 대조해 1~5점으로 채점한다.
  A 기여·포지셔닝 / B 이론적 근거 / C 방법 정당화 / D 검증 엄밀성 / E 결과 해석·스토리텔링 /
  F 논의·한계·함의 / G 내적 일관성·수치 정합 / H 서술 품질·독자 적합성
- 각 축에서 발견한 문제는 **원고 위치 + 문제 + 왜 문제인지(Tier 기준) + 요구 조치**로 적는다.
- `python scripts/recommend.py --tier 1 --scores A=2,B=2,C=3,D=3,E=3,F=2,G=4,H=3` 로
  권고(Reject / Major / Minor / Accept)를 산출한다. 스크립트는 Tier별 결정 규칙을 고정해
  판단 흔들림을 막는 용도이며, 최종 권고는 심사자 판단으로 조정 가능하다(조정 시 이유 기록).

### Step 3. 심사평 작성 → `references/review-format.md`, `references/phrasebank.md`
- 구조: Summary → Overall Assessment → Major comments → Minor comments (+ 2차 이상이면
  Response Evaluation). 권고 등급은 **본문에 쓰지 않고** 편집자용 confidential 블록에만 쓴다.
- Major는 3~6개로 압축(MECE). 사소한 것을 Major로 올리지 않는다. Minor는 번호 목록.
- 문체: 격식 영어, 유감 어조("I regret that…", "I am not convinced that…")로 강도를 전달.
  공격적 표현·인신 비판 금지. 각 코멘트는 저자가 바로 행동으로 옮길 수 있게 끝낸다.
- 국문 요약: 개조식 보고체(명사형 종결), 두괄식 — 판정·핵심 사유 3개·Major 목록·Minor 개수.

### Step 4. 셀프 체크
- [ ] Tier 판정과 근거가 명시됐는가
- [ ] Major 각각이 원고 특정 위치를 가리키는가 / 서로 겹치지 않는가(MECE)
- [ ] Tier 3 원고에 Tier 1 잣대를 들이대지 않았는가(과잉 요구), 반대로 Tier 1에서 관대하지 않았는가
- [ ] 자기모순(예: LLM 불투명성을 비판하며 LLM 사용) 여부를 점검했는가
- [ ] 본문에 reject/accept 같은 등급 단어가 없는가
- [ ] 국문 요약이 개조식·두괄식인가

## 모드별 차이

| 모드 | 추가로 할 것 |
|---|---|
| 실제 저널 심사 | 편집자용 confidential 권고 포함. 저자 정보가 있어도 무시(더블블라인드 전제) |
| 투고 전 셀프리뷰 | 가장 까다로운 리뷰어를 가정. 권고 대신 "이 Tier 통과 확률"과 **수정 우선순위 Top 5**를 제시. 리비전 가이드(어떤 실험·문단을 추가할지)까지 작성 |
| 2차 이상 심사 | 이전 코멘트별로 ① 실질 반영 ② 형식 반영(문구만) ③ 미반영 분류. 응답서가 수정 본문 복붙·반복 감사 문구로 채워졌으면 지적 |
| 학위논문 심사 | 세 개 이상의 하위 연구가 있으면 **연구 간 관계·흐름도**부터 점검. 산출물이 초안(draft)인지 최종물인지 포지션 명시 요구. 국문 "~함/~필요함" 체 |

## 분야 특이 체크 (특허분석·LLM·tech mining 원고일 때)

이 주제 원고는 정보과학 논문처럼 읽히기 쉽다. Tier 1 TM 저널에서는 다음이 반복적으로 문제된다:
- 서사가 데이터마이닝 절차에서 시작함 → 기술인텔리전스/TM의 문제에서 시작해야 함
- 각 태스크가 "어떤 TM 의사결정에 기여하는지" 이론적 연결 부재
- 단일 기법 채택 근거 없음(왜 BERTopic인지, 대안 대비 무엇이 나은지), 프롬프트 전략 비교 없음
- LLM-as-a-judge에만 의존, 골드스탠다드·전문가 검증·평가자 간 신뢰도(κ, ICC, α) 미보고
- 상용 LLM 의존 → 재현성·모델 드리프트 미논의
- 결과 섹션이 성능 검증 나열이고 도메인 사례의 스토리텔링이 없음
- Discussion에 문헌 인용이 없어 담론 내 위치가 불명확
- 도출된 "솔루션"이 이미 존재하는 것일 수 있음(특허 외 논문 등 소스 필요)을 언급하지 않음
상세 문항과 표현은 `references/critique-axes.md` D·E·F 축 참조.

## 주의
- 원고를 읽지 않은 축에 대해 점수를 매기지 않는다. 읽을 수 없는 부분(그림·부록 누락)은 "확인 불가"로 표기.
- 저널 IF·랭킹은 변하므로 기억에 의존하지 말고 불확실하면 검색해 연도와 함께 기록한다.
- 심사평은 사용자의 이름·소속이 드러나는 표현을 넣지 않는다.
- 사용자가 리뷰어 코멘트에 **대응**(response letter, 리비전 문구)을 원하면 이 스킬이 아니라
  `tm-paper-style`을 사용한다.
