# 평가 축 A–H: 채점 기준과 점검 문항

각 축을 1~5점으로 채점한다. 점수 앵커는 아래 표를 따르되, **Tier 요구 프로파일**
(`journal-tiers.md`)에 비추어 "이 Tier에서 이 상태가 통과 가능한가"로 읽는다.
점검 문항은 사용자가 받았던 심사평(TFSC EE·리뷰어, 박사논문 심사위원)과 직접 쓴 심사평에서
반복된 비판을 일반화한 것이다. 문항 뒤 `→` 는 코멘트를 쓸 때의 요구 조치 방향.

공통 점수 앵커: 5 = 해당 Tier 최상위 논문 수준 / 4 = 사소한 보완 / 3 = 실질 보완 필요 /
2 = 핵심 결함 / 1 = 부재 또는 오류

---

## A. 기여와 포지셔닝 (Contribution & Positioning)

가장 자주 reject 사유가 되는 축. "새로운 방법"과 "새로운 기여"는 다르다.

- 논문이 어느 **담론(discourse)**에 속하는지 명시했는가? 기존 연구 흐름에서 이 연구의 위치가
  한 문장으로 말해지는가 → 연구 포지션을 Introduction과 Discussion 양쪽에 명시 요구
- 기여가 motivation 안에 포함되어 있는가? 독자가 "왜 이 연구가 필요한지"와 "무엇이 새로운지"를
  Introduction 끝에서 알 수 있는가
- 제목이 약속한 것과 본문이 한 것이 일치하는가? (예: 제목은 특허분석, 내용은 정보검색)
- 기존 방법과 **무엇이 다른지**가 태스크/프로세스 단위로 구체적인가? "LLM을 썼다"가 아니라
  "어느 단계의 어떤 대상에 LLM을 적용했고 기존 연구는 어디에 적용했는가"
- 확장성·일반화 주장이 과대하지 않은가? → 핵심 범위만 남기고 축소 요구
- 산출물의 성격이 명확한가 — 최종 답인가, 전문가가 다듬을 **초안(draft)**인가? (특허 데이터에
  모든 문제가 정리돼 있지 않으므로 대개 초안임을 명시해야 함)
- Tier 1 전용: 이 연구가 TM 커뮤니티의 **어떤 의사결정 문제**에 기여하는가가 이론적으로
  뒷받침되는가? 정보과학자가 아니라 경영·정책 연구자가 왜 읽어야 하는가?

## B. 이론적 근거 (Theoretical Grounding)

- 새 개념·용어(예: Target–Symptom, strategy)를 도입했다면 정의·선행 개념과의 관계·왜 필요한지가
  있는가? 정의 없는 신조어는 Tier 1에서 major
- **근거 없는 개념 동일시**가 있는가? (예: 특허 = 기술, 토픽 = 기술 기회, IPC 동시출현 = 융합)
  → 등치의 근거를 문헌 또는 데이터로 요구
- 문헌 검토가 정보과학 절차(데이터마이닝 흐름, LDA→BERT→LLM) 서술인가, TM의 문제
  (기술인텔리전스·기회탐색·R&D 기획)에서 출발하는가?
- 관련 이론(recombinant innovation, analogical transfer, knowledge recombination, TRIZ 계열 등)을
  써야 하는 주장에 이론 인용이 있는가?
- 갭 진술이 실제 갭인가? "limited studies" 주장에 최근 2년 문헌이 빠져 있지 않은가

## C. 방법 정당화 (Method Justification)

- 각 처리 단계의 기법 선택에 **대안 대비 근거**가 있는가? (BERTopic vs PatentSBERTa 유사도 군집,
  LLM vs 지도학습, 원문 vs 재구성 statement 입력)
- 선택 근거가 논리적으로 일관되는가? 자기모순 점검:
  - LLM의 불투명성을 비판하면서 LLM을 평가자로 쓴다
  - 비용 우위를 주장하면서 LLM 변동비와 지도학습 고정비를 다른 잣대로 비교한다
  - 거시 분석 도구(IPC 동시출현 네트워크 등)를 소규모·단일국가 데이터에 적용한다
  - Subclass 수준 분석으로 세부 기술 융합을 주장한다
- 프롬프트가 쓰였다면 zero/few-shot·CoT 등 전략 비교가 있는가, 프롬프트 전문이 부록에 있는가
- 하이퍼파라미터·모델 버전·온도·시드·검색식·데이터 기간이 재현 가능하게 적혀 있는가
- 상용 LLM 의존 시 모델 드리프트·재현성 한계를 인정하고 완화책(출력 아카이브, 온도 0 반복)을
  제시했는가

## D. 검증 엄밀성 (Validation Rigor)

Tier 1에서 가장 많은 Major가 나오는 축.

- 골드스탠다드가 있는가? 있다면 표본 추출 방식, 주석자 수·전문성, **평가자 간 신뢰도**
  (Cohen's κ, Fleiss' κ, ICC, Krippendorff's α)가 보고됐는가? 낮은 값(예: ICC 0.44)을 "충분"으로
  포장하지 않았는가
- 베이스라인이 있는가? 최신 방법(PatentSBERTa, SciBERT 등 도메인 모델)과 비교했는가,
  통계적 유의성(Friedman, paired t, Bonferroni)을 검정했는가
- **LLM-as-a-judge에만 의존**하지 않는가? 인간 평가와의 일치도가 있는가? 위치 편향 등
  judge 편향을 점검했는가
- 전문가 검증이 있다면: 몇 명, 어떤 배경, 몇 라운드, 질문 내용, 라운드 간 동일 인원 여부,
  전문가 간 의견 일치도 → 절차 상세 요구
- 단일 도메인 사례만으로 일반화하는가? 검증(validation)과 시연(demonstration)을 구분해 썼는가
- 부분 검증을 전체 검증처럼 쓰지 않는가(예: 문제 추출 단계만 전문가 비교하고 전체 파이프라인
  신뢰성을 주장) → 한계 명시 + 향후연구
- **end-to-end 검증**: 전체 방법론을 전통적·대안 NLP 접근과 비교한 절이 있는가 (결론의 한 문단으로
  때우지 않았는가)
- 강건성: 반복 실행 결과, 민감도 분석, ablation

## E. 결과 해석과 스토리텔링 (Results & Case Narrative)

- 결과 섹션이 성능 지표 나열(validation)인가, 특정 기술 도메인에서 **모든 모듈이 연결된 일관된
  사례**(storytelling)인가?
- 정량 결과와 도메인 전문가의 정성 논의가 상호작용하는가? ("이 클러스터가 왜 중요한가"에
  전문가 해석이 붙는가)
- 사례에서 도출된 인사이트가 실제 R&D 의사결정으로 이어지는 형태인가, 표 몇 개로 끝나는가
- 그림·표가 본문에서 참조되고 해석되는가? 시각화가 표보다 정보를 더 주는가(아니면 표로)
- 구체적 사실 질문으로 검증: "이 특허는 누가 출원했는가", "이 클러스터의 대표 특허는 실제로 그
  문제를 다루는가" — 답할 수 없으면 해석이 근거 없는 것

## F. 논의·한계·함의 (Discussion, Limitations, Implications)

- Discussion에 **문헌 인용이 있는가?** 없으면 "고립된 연구"로 읽힌다 → 기존 접근 대비 부가가치를
  문헌과 대조해 재작성 요구
- 한계가 정직한가: 잔존 주관성, 입력 데이터의 구조적 한계(표준화된 배경 섹션 부재 등), 도출
  솔루션이 이미 존재하는 것일 가능성, 특허 외 소스(논문) 필요성
- 실무 함의가 사용자 시나리오 수준으로 구체적인가(누가, 어느 의사결정 단계에서, 무엇을 얻는가)?
  기술인텔리전스의 목적·의사결정 수준 분류에 매핑됐는가
- 결론이 Introduction의 RQ에 하나씩 답하는가
- 한계–향후연구가 짝지어져 있는가

## G. 내적 일관성과 수치 정합 (Internal Consistency)

- 섹션 간 모순: 6.3에서는 1개 도메인 검증, 6.4에서는 3개 도메인 검증이라 쓰는 식
- 수치 불일치: 클러스터 수, 후보 총수, F1, 비용이 본문·표·그림·부록에서 같은가
- 표에서 비교한 여러 모델 중 후속 실험에 무엇을 썼는지 명시됐는가
- 수식 표기·변수 명칭이 통일됐는가, 정의되지 않은 지표(Z-score, Ratio 등)가 없는가
- 설문 결과와 응답자 프로필이 제시됐는가

## H. 서술 품질과 독자 적합성 (Writing & Audience Fit)

- 저널 독자에게 맞는 서사 순서인가(Tier 1 TM: 문제 → 왜 특허 → 왜 LLM. 정보과학 순서 아님)
- 문단이 두괄식이고 주장–근거–예시–함의 순서인가
- 형식: 참고문헌 양식, 약어 첫 등장 풀이, 그림 해상도, 부록 교차참조, 오탈자(띄어쓰기 붙음 등)
- 응답서(2차 이상): 수정 본문 복붙·반복 감사 문구로 채워졌는가 → "무엇을 어떻게 바꿨는지"만
  간결히 요구

## 2차 이상 심사 시 코멘트별 분류

| 분류 | 판정 기준 | 코멘트 예 |
|---|---|---|
| 실질 반영 | 요구한 실험·재구성이 실제로 추가됨 | "The added Section 5.2 adequately addresses my concern." |
| 형식 반영 | 문장 추가·용어 변경만, 핵심 요구 미충족 | "The revision acknowledges the issue but does not resolve it: …" |
| 미반영/회피 | 답변만 있고 원고 변화 없음, 또는 반박이 근거 없음 | "I could not locate the corresponding change in the manuscript." |

이전 라운드에서 "마지막 기회"가 언급됐는데 실질 반영이 절반 미만이면 Reject 권고가 정당하다.
