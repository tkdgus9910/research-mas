# 복잡도 예산

단순화 감사가 쓰는 기준이다. 아래 값은 기본값이며 사용자가 연구 성격에 맞게 고친다. 예산을 넘는 설계는 넘는 이유를 설계서에 적어야 한다.

| 항목 | 예산 | 세는 방법 |
|---|---|---|
| 실험 단계 수 | 3~5개 | `configs/default.yaml` 의 `stages` |
| 단계별 코드 길이 | `stage.py` 200줄 이하 | 빈 줄·주석 제외 |
| 단계별 파라미터 수 | 7개 이하 | `configs/default.yaml` 의 `params.<단계>` |
| LLM 을 호출하는 단계 | 1개 이하 | `map_cached` 등 LLM 호출이 있는 단계 |
| 프롬프트 파일 | 2개 이하 | `prompts/*.md` |
| 외부 의존 패키지 | 10개 이하 | import 되는 서드파티 패키지 |
| 전체 재실행 명령 | 1개 | `python run.py` |
| 수동 절차 | 0개 | 손으로 파일을 옮기거나 값을 고치는 단계 |

## 원칙
- 구성요소는 "빼면 결과가 달라진다"는 근거가 리포트에 있을 때만 남긴다.
- 쓰이지 않는 옵션, 미래를 위한 추상화, 일어나지 않는 경우의 예외 처리를 두지 않는다.
- 1인 연구 코드에 워크플로 엔진, 컨테이너, 데이터 버전 관리 도구를 들이지 않는다.
